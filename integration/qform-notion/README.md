# Бесплатная интеграция QForm → Notion для «Дома №13»

Это отдельный **Cloudflare Worker**, а не изменение HTML сайта. Сайт на GitHub Pages продолжает работать как сейчас. Обе формы QForm отправляют события напрямую Worker, а он создаёт строки в существующей базе Notion **«Заказы светильников»**.

**Статус:** код подготовлен в ветке GitHub. До регистрации Cloudflare, создания секретов, настройки вебхуков и живого теста заявки автоматически НЕ передаются.

## 1. Что нужно подключить

- Бесплатный аккаунт [Cloudflare](https://dash.cloudflare.com/sign-up).
- Интеграция [Notion API](https://www.notion.so/profile/integrations) с правом **Insert content** для конкретной базы «Заказы светильников».
- Доступ к кабинету QForm, где созданы обе формы.
- Node.js для локального развёртывания с Wrangler; альтернативно можно импортировать GitHub-репозиторий через панель Cloudflare Workers (указать путь проекта \`integration/qform-notion\`).

**Notion database/data source:** \`9f0d20ce-441c-4d6e-b833-0bfe4bfcca21\` (уже указан в \`wrangler.toml\`).

## 2. Развёртывание

1. Создать аккаунт Cloudflare Workers Free.
2. Открыть этот каталог \`integration/qform-notion\` в локальном клоне репозитория.
3. Выполнить \`npm install\`, затем \`npx wrangler login\`.
4. Выполнить \`npx wrangler deploy\`. Получить URL вида \`https://dom13-qform-notion.<аккаунт>.workers.dev\`.
5. Создать Notion API integration и вручную предоставить ей доступ к базе «Заказы светильников». Если доступна настройка прав, ограничить их созданием/чтением страниц этой базы.
6. В панели **Cloudflare > Workers & Pages > dom13-qform-notion > Settings > Variables and Secrets** создать следующие переменные **типа Secret**:

   | Имя | Значение |
   |---|---|
   | \`NOTION_TOKEN\` | токен Notion integration; нигде не публиковать |
   | \`QFORM_READY_SECRET\` | уникальная случайная строка длиной от 32 до 64 символов |
   | \`QFORM_CUSTOM_SECRET\` | другая уникальная случайная строка длиной от 32 до 64 символов |

   При необходимости добавьте \`QFORM_READY_FORM_ID\`, \`QFORM_CUSTOM_FORM_ID\` после проверки реальных \`form_id\` из QForm: Worker дополнительно отклонит события с неверными ID. Это рекомендуемая дополнительная защита.

   **Не храните ни один секрет в открытом репозитории, публичных документах или в чате.**

7. Если известные названия вопросов QForm отличаются от стандартных, добавьте переменную \`FIELD_ALIASES_JSON\`, например:
   \`{"name":["Как вас зовут?"],"phone":["Ваш номер для связи"],"city":["Город доставки"]}\`.
   Структуру и реальные названия вопросов определить только по тестовому webhook, не угадывать.

## 3. Подключение форм QForm

В кабинете QForm открыть **каждую форму → Интеграции → Webhook** (конкретное название пункта интерфейса может отличаться). Выбрать событие создания новой заявки, метод **POST**, JSON-данные:

- **Форма готового светильника:** \`https://dom13-qform-notion.<аккаунт>.workers.dev/qform/ready/<QFORM_READY_SECRET>\`
- **Форма индивидуального проекта:** \`https://dom13-qform-notion.<аккаунт>.workers.dev/qform/custom/<QFORM_CUSTOM_SECRET>\`

**Важное ограничение безопасности:** если интерфейс QForm не позволяет отправить секретный URL целиком, эту схему потребуется адаптировать. Адрес вебхука является конфиденциальным, потому что QForm не предоставляет нам подтверждённую подпись запроса.

Не нужно менять адреса форм, встроенных в HTML сайта:
- Готовая форма: https://qform.link/form_k6NCF1Kdeb-29eFXZ3oMLHAavJ_--wg9
- Индивидуальная: https://qform.link/form_6lEWxLowOGEZQxtT-NMGU8PUH1ko-wco

## 4. Какие поля создаёт Worker

| Поле Notion | Содержимое |
|---|---|
| Заказ | «Заявка с сайта · Дом №13» или «Свой дом» и короткий идентификатор |
| Источник | Сайт |
| Этап | Заявка |
| Тип | Готовый светильник / По своему дому |
| Форма QForm | Вид использованной формы |
| Имя, Телефон, Способ связи, Город, Комментарий | Ответы QForm, если удаётся распознать имена полей |
| Дата заявки | Время обработки события Worker |
| ID заявки QForm | Исходный идентификатор заявки, если присутствует, либо SHA-256 отпечаток ответов |

Нераспознанные поля сохраняются в **теле приватной страницы Notion** в разделе «Ответы из QForm», чтобы ничего не потерялось. Это может содержать персональные данные, ограничьте доступ к базе.

**Склад не резервируется автоматически при создании заявки.** Резервирование происходит позднее, при подтверждении заказа.

## 5. Обязательная проверка перед запуском

1. Открыть \`https://<адрес Worker>/health\`; ответ должен содержать \`{"ok":true,...}\`.
2. Создать тестовое обращение в форме «Дом №13».
3. Проверить, что новая строка появилась в Notion, корректно заполнены имя, телефон и тип, а «Этап» = «Заявка».
4. Аналогично проверить вторую форму.
5. Проверить дважды доставленный **один и тот же webhook**: должна сохраниться одна запись.
6. Проверить, что с неверным ключом URL Worker отвечает 404.
7. После этого включить доставку боевых заявок. Проверить, что уведомления QForm по Telegram/email продолжают работать.

## 6. Ограничения и безопасность

- Бесплатный план Cloudflare Workers достаточно велик для небольшого числа заявок, но действует лимит бесплатного тарифа.
- **Защита от дублей — best effort.** Worker ищет в Notion запись с тем же идентификатором перед вставкой. Почти одновременные повторные вызовы могут успеть создать дубль, так как Notion не даёт уникального ограничения. При росте потока добавим бесплатный Cloudflare D1 с уникальным ключом.
- Если QForm не передаёт уникальный ID заявки, вычисляется отпечаток из содержимого формы. Две отдельные, полностью идентичные заявки будут расценены как один дубль. Это поведение нужно подтвердить на реальном QForm событии, прежде чем включать эксплуатацию.
- Все секреты — только в хранилище секретов Cloudflare, не в GitHub Pages. При компрометации адреса вебхука меняйте его секрет.
- Обработка включает ФИО/телефоны и может затрагивать требования законодательства о персональных данных РФ (например, локализацию баз данных граждан РФ). **Перед боевым включением обязательно отдельно проверить законность передачи и хранения этих данных в Cloudflare/Notion**; если такой способ не подходит, выбрать инфраструктуру и архитектуру обработки, соответствующие требованиям. Пока это технический прототип, не введённый в эксплуатацию.
- У Worker нет администраторского доступа к QForm, Cloudflare или персональной почте; фактическое включение требует действий владельца аккаунтов.
